01 / METHOD

One optimization loop.Two database decisions.

QDBO separates database-specific modeling from the shared iterative quantum search.

01

Encode

Translate database costs and constraints into a binary quadratic model.

02

Map & sample

Embed the model on available hardware and collect quantum samples.

03

Refine

Use sample statistics to update the model and improve the next search step.

02 / FRAMEWORKS

See how QDBO fitseach use case.

Q²O-QDBO · JOIN ORDERING

From query graph to executable join plan.

Q²O-QDBO builds a join-ordering QUBO, runs the iterative quantum search, and decodes the result into a PostgreSQL-compatible plan.

IS-QDBO · INDEX SELECTION

From workload evidence to a budgeted index set.

IS-QDBO models index benefit and storage cost as a constrained QUBO, then returns a set that can be replayed against PostgreSQL.

03 / REPRODUCE

Start from one clean repository.

quick-start.sh
$ git clone https://github.com/ihanwen99/VLDB26-QDBO.git
$ cd VLDB26-QDBO
$ python -m venv .venv && source .venv/bin/activate
$ pip install -e .
$ bash qdbo/embedding/build_cpp_embed.sh
$ cp config.example.env config.env

Code, build source, workloads, and paper inputs are included.

Configure D-Wave Leap for quantum runs. Add PostgreSQL and workload data only when reproducing measured database execution. Generated results stay outside Git.
